# image-gen-fal

A ZeroClaw **WIT component** tool plugin that generates images from text prompts
using [fal.ai](https://fal.ai) (Flux models). It implements the `tool-plugin`
world from `wit/v0` and compiles to a `wasm32-wasip2` component.

## What it does

Exposes one tool, `image_gen_fal`. Given a prompt it POSTs to
`https://fal.run/<model>`, then returns the generated image's URL along with the
model and prompt used.

## Why it lives here and not in core

This tool used to ship inside the ZeroClaw binary as
`zeroclaw-tools/src/image_gen.rs`. Core already classified it as
`ToolKind::Plugin`, and it is a paid third-party API — so the default binary
carried an integration most users never call, plus a credential path for a
service they may not have an account with. Moving it out keeps core smaller and
puts the fal.ai dependency, and its key, behind an explicit install.

## Credentials come from config, not the environment

The 0.1.0 release read `FAL_API_KEY` straight from the process environment via a
`zc_env_read` host function. Raw environment access was removed from plugins in
[zeroclaw#8137](https://github.com/zeroclaw-labs/zeroclaw/pull/8137), so the key
is now read from this plugin's own jailed config section, which the host injects
into `execute` arguments as `__config` under the `config_read` permission.

That is a **breaking change** for anyone on 0.1.0 — hence 0.2.0. Setting
`FAL_API_KEY` in the environment no longer has any effect; move the key into
config:

```toml
[[plugins.entries]]
name = "image-gen-fal"
enabled = true

[plugins.entries.config]
api_key = "<your fal.ai key>"
```

The plugin can never read the global config or another plugin's section. Without
`config_read` it receives an empty map and fails with a message naming the
config key.

## Parameters

| Parameter | Required | Default | Meaning |
|---|---|---|---|
| `prompt` | yes | — | Text description of the image to generate. |
| `size` | no | `square_hd` | One of `square_hd`, `landscape_4_3`, `portrait_4_3`, `landscape_16_9`, `portrait_16_9`. |
| `model` | no | `fal-ai/flux/schnell` | fal.ai model path, e.g. `fal-ai/flux-pro/v1.1`. |

`model` is validated before it is interpolated into the request URL: values
containing `..`, `?`, `#`, `\`, or a leading `/` are rejected, so a caller
cannot escape the `fal.run` path or smuggle a query string onto the request.

Upstream error bodies are truncated to 500 characters, so a large HTML error
page from fal.ai cannot flood the agent's context window.

## Layout

The pure request/response logic lives in [`src/fal.rs`](./src/fal.rs) with no
wasm dependency, so it compiles and tests on the host with a plain `cargo test`.
[`src/lib.rs`](./src/lib.rs) is a thin component shim that adds config lookup and
the `wasi:http` call, reusing the exact same logic.

## Build and test

```sh
cargo test                                        # host tests, no wasm toolchain
rustup target add wasm32-wasip2
cargo build --target wasm32-wasip2 --release      # -> image_gen_fal.wasm
```

`registry.json` is generated by the publish workflow; it is not hand-edited here.
